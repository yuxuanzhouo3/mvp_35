# Agent 评测卡 · 5 Recall Bot（Event-triggered Sequential Agent）

| 项 | 值 |
| --- | --- |
| 产品落点 | Recall · 冷启文案 |
| 架构 | 规则入队 → 固定序列（D0 / D3 / …）→ 每步 LLM 写一封 → 批准后发 |
| 约束 | **是否流失 / 是否入队只由规则**；模型只写文案 |

---

## 商业 KPI

| 主扛 | 目标 | Agent 贡献方式 |
| --- | --- | --- |
| `ActR_cold` | ≥25% | 冷启序列文案 → open∨reply |
| `RecR` | ≥10% | 召回触达 → 回暖 |
| `ActT` | P50 ≤24 h | 入队 → 首封 delivered |
| `RecT` | P50 ≤24 h | 触发 → 首封 delivered |

告警：ActT / RecT 的 P95 &gt;72h。

---

## 技术指标

| 代号 | 门槛 | 测法 |
| --- | --- | --- |
| `NoBypass` | =100% | 模型无法「强制入队」或「取消流失标记」 |
| `HITLGate` | =100% | 序列每封仍需批准（或策略允许的预批模板） |
| `SchemaOK` | ≥98% | 步进、模板变量、退订齐全 |
| `P50_Lat` | 入队后首封生成+入发送队列支撑 ActT/RecT | 文案可预生成 |
| `DegradeOK` | 100% | 无模型 → 序列模板信 |

---

## 其他

- 冷启与召回共用触达管道与红线。
- 不把召回成功算进普通 AR 的 W，除非产品定义明确「回暖后再次获客」事件（默认 RecR 单列）。
- 对赌一般不绑召回；若合同包含唤醒沉默买家，须在 `success_event` 写清并仍 `exclude_from_ar`（B9）或单独科目。

---

## 验收用例（最小）

1. 规则命中流失 → 入队；模型建议「不要召回」无效。
2. 入队后 24h 内有首封 delivered（批测时钟可加速）。
3. 未批准 → 无 delivered；批准后 RecR/ActR_cold 分母分子可算。
4. 关模型 → 模板序列仍可走完人审发送。
