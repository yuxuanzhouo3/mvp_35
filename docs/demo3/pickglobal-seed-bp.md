## 1. 执行摘要

PickGlobal 服务中国制造商、出口商、独立卖家与跨境电商团队，把「选品算清」和「获客做完」放进同一个工作台。

产品只做两条路径，不新开第三条产品线：

- **路径 A · 选品分析报告**：自有商品入库或帮我选品 → 规则引擎算利润 / 税务 / 时效 / 风险 → 四维报告 → **一键获客**。  
- **路径 B · 九路获客经营**：线索发现 → 人工批准后触达 → 成交标记 → 冷客启动 / 流失召回。

硬约束决定了产品气质：

- **金额只由规则引擎计算**（`pg-rules-1.0`），模型只写解释，不能改利润、分数或风险。  
- **触达必须人审**：AI 起草 → 人工批准 → 再发送。  
- **看板八率 + 五时效**：分母为 0 显示「—」，不把空样本写成成绩。

当前阶段：可演示的全链路 MVP 已上线（Web + 微信小程序能力、微信 / 支付宝支付打通、租户登录、账单套餐、规则选品、九路获客骨架）。生产环境版本 `pro` 为 `1.2`；测试线已推进到 `1.9`。种子轮目标是把「可演示」推到「可规模获客 + 可复算的 ARR」，并完成海外触达合规与正式邮件通道。

**拟融资用途（摘要）**：产品与数据（选品货架与线索质量）、合规触达（正式邮件 / 通道与审核）、增长（内容与渠道销售）、工程与云成本。具体金额区间与股权结构见第 10–11 节，可按投资人条款协商。

**投资人一页结论**

| 问题 | 我们的答案 |
| --- | --- |
| 卖什么？ | 可审计的选品报告 + 可批准的获客工作台（SaaS 订阅为主） |
| 为何能赢？ | 规则引擎锁金额；人审锁触达；KPI 口径写进产品 |
| 现在融什么？ | 把可演示 MVP 推到可规模获客与可复算 ARR |
| 风险最大的点？ | 海外触达合规与货架稳定性——已列入用途与里程碑 |
| 怎么验？ | 线上同屏 + demo3 教程 + 支付 / 看板样本，不做虚构 ARR |

## 2. 问题与机会

### 2.1 卖家真实痛点

跨境卖家每天同时面对三件事，但工具是割裂的：

| 痛点 | 现状 | 后果 |
| --- | --- | --- |
| 选品算不清 | Excel、平台后台、货代报价混用；模型「拍脑袋」给利润 | 高流量低利润、退货与税务意外 |
| 获客做不完 | 线索散落在电商站内信、社交私信、展会名片、代理表格 | 跟进断层；冷客与沉默买家无人管 |
| 结果看不懂 | KPI 口径不一；分母为 0 时硬写成 0% | 团队误判；无法复盘「哪一步坏了」 |

### 2.2 为什么是现在

1. **中美 / 中港 / 中澳**仍是中国卖家主航道；税务与运费波动迫使「先算后卖」。  
2. 平台与社交触达合规收紧，**未审群发**风险上升，人审工作流成为刚需。  
3. 大模型普及后，市场充斥「AI 选品 / AI 写邮件」叙事；买家开始要求**数字可审计**，规则引擎 + 模型解释是正确分工。  
4. 微信小程序与手机端成为卖家日常入口，**同一工作台多端**比「再装一个桌面工具」更贴合使用习惯。

### 2.3 我们不做的事

- 不做第三条产品线（例如独立供应链金融、独立建站）。  
- 不让模型改金额、机会分或风险等级。  
- 不在 DEMO 阶段假装已开通正式海外群发；邮件通道先 mock / 沙箱，合规后再上线。

## 3. 解决方案与产品

### 3.1 一句话

> PickGlobal = **可复算的选品报告** + **可批准的九路获客** + **可解释的八率五时效看板**。

### 3.2 路径 A：选品分析报告

```text
双向入口（手动 / CSV / 帮我选品）
        ↓
路线与市场（默认中国→美国；可切国内 / 香港 / 澳大利亚 / 美国→中国）
        ↓
规则引擎 pg-rules-1.0（利润 · 税 · 时效 · 风险）
        ↓
四维报告 + 一键获客（携带 seed_analysis_id）
```

特色：

- 自有导入与货源目录汇入**同一商品库**。  
- 改市场或成本后，旧报告标为过期，必须重算。  
- 1688 等货源价按套餐刷新（免费档小时级；付费档更频，并有手动刷新额度）。  
- 报告在页面中央弹层阅读，降低「分析完就走」的摩擦，抬升行动率 ActR。

### 3.3 路径 B：九路获客

| 代号 | 路径 | 角色 |
| --- | --- | --- |
| B1 | 电商（Amazon / Temu / Walmart / 淘宝 / 拼多多等） | 主获客 |
| B2 | 社交（LinkedIn / Facebook / 微信 / 短视频等） | 主获客 |
| B3 | 线上展会 | 主获客 |
| B4 | 代理渠道（分成账本） | 主获客 |
| B5 | 智慧大脑（企查查等 enrichment） | 主获客 |
| B6 | GEO / SEO | 优化；可自销 |
| B7 | AI 内容工厂 + 数字人 | 优化；占位 |
| B8 | 跨境元素复现（中美 / 中港 / 中澳话术包） | 优化 |
| B9 | RAAS（卖结果抽成） | 本品销售 |

统一漏斗：`发现 → 线索池 → 触达活动 → 草稿 → 批准 → 发送 → 成交 / 冷启 / 召回`。九路进**同一线索池**，用 `source_channel` 区分来源。

### 3.4 看板：八率 + 五时效

北星指标是**获客率 AR**（送达后 14 天内有效获客 ÷ 送达人数，目标 ≥8%）。其余七率与五时效见附录。演示账号在完成「分析 → 一键获客 → 发现线索」后，看板按**本账号最近 30 天**计算；尚无成交时，部分指标显示「—」或全站平均，避免虚高。

### 3.5 用户可见入口

- Web 工作台：看板 / 选品分析 / 获客经营 / 账单。  
- 官网右上角「操作演示」：云健口播教程（`demo3` 成片含八率五时效逐卡讲解）。  
- 微信小程序与多端适配（手机底栏、iPad 并排等）。  
- 登录前勾选《用户守则》与《隐私条款》。

### 3.6 demo3 演示脚本（投资人同屏建议）

配套成片约 5 分钟用户教程；投资人演示可压缩为：

| 步 | 画面 | 要证明的点 |
| --- | --- | --- |
| 1 | 官网两条路径 | 产品边界清晰，无第三条线 |
| 2 | 登录勾选守则 | 合规入口先于账号 |
| 3 | 路线条默认中国→美国 | 市场可切换，商品库统一 |
| 4 | 写入商品 → 分析 → 报告弹层 | 规则版本可见；利润可复算 |
| 5 | 一键获客 → 电商发现 | 报告编号进入获客；九路分页 |
| 6 | 草稿 → 批准 | 未批准不能发 |
| 7 | 八率五时效 + 点开卡片 | 分母为 0 显示「—」；公式可解释 |

演示保温杯样例（规则引擎，非模型编造）：利润率约 **42.1%**，净利润约 **$16.44**，机会分 **67**，风险 **低**，规则版本 **pg-rules-1.0**。

## 4. 市场与客群

### 4.1 目标客户（ICP）

| 分层 | 画像 | 核心需求 | 付费动机 |
| --- | --- | --- | --- |
| 核心 | 年出口 / 跨境 GMV 中小卖家，1–20 人运营 | 选品不亏 + 线索跟进 | 月费换人力与试错成本 |
| 扩展 | 工厂型出口商、贸易公司 | 多 SKU 导入、代理分成 | 年费 + 分成账本 |
| 远期 | 渠道 / 服务商（B4 / B9） | 批量获客、结果抽成 | 抽成与账户销售 |

首选市场叙事：**中国货源 → 美国货架**；路线条已支持国内销售、中港、中澳、美→中，便于同一产品扩市场，不扩产品线。

### 4.2 市场结构（定性）

种子轮不编造未经审计的 TAM 美元数。我们采用可验证的拆法：

1. **可服务卖家数** ≈ 使用跨境选品 / 货代 / ERP / 邮件触达工具的中国卖家与工厂客户。  
2. **可收费钱包** ≈ 订阅（成长 / 规模档）+ 通道成本加成 + 远期 RAAS 抽成。  
3. **我们切的楔子** = 「报告可审计 + 获客可批准 + KPI 口径固定」——不是又一个选品榜单，也不是又一个群发器。

### 4.3 早期验证信号（产品侧）

- 演示链路可在本地 / 线上走通：入库 → 分析 → 报告弹层 → 一键获客 → Temu 等发现 → 草稿批准。  
- 支付：微信与支付宝在测试线已成功。  
- 规则版本与解释模型字段对外可见，便于销售时演示「模型不改数」。  
- 用户教程与 demo3 成片覆盖守则勾选、路线条、1688、八率五时效卡片。

定量收入与留存以融资后 90 天试点合同为准，本节不虚构 ARR。

## 5. 商业模式

### 5.1 当前套餐（产品内已配置）

| 档位 | 月价（标价） | 年付 | 说明 |
| --- | --- | --- | --- |
| 免费 | ¥0 | — | 入门；货源刷新频率较低 |
| 成长 growth | ¥299 / 月 | 年付 = 0.7 × 月价 × 12 | 更高刷新频率与额度 |
| 规模 scale | ¥999 / 月 | 同上规则 | 更高海外货架上限与 AI 日限 |

另有海外货架条数上限、按档手动刷新次数、邀请奖励与利润分成计划（`pg-share-1.0`）等增长杠杆。代理分成与 RAAS 抽成走**整数分 + 幂等账本 + 验签入账**，与订阅可并存。

### 5.2 收入结构（目标形态）

```text
经常性收入 ARR  ≈  订阅（成长 / 规模）
一次性 / 浮动     ≈  按次能力、通道成本加成
结果收入         ≈  RAAS / 代理分成（不污染普通 AR 口径）
```

### 5.3 单位经济（框架）

| 项 | 种子轮原则 |
| --- | --- |
| 获客成本 CAC | 先做内容与演示驱动；付费投放等口径稳定后再放大 |
| 毛利 | 云托管可缩到 0 副本；按使用计费；避免探活常驻 |
| 交付成本 | 规则算数不烧大模型；模型仅解释与文案 |
| 扩张 | 新平台 = 新 Provider，不新开线索主表、不新开产品线 |

## 6. 竞争与壁垒

### 6.1 竞品类型

| 类型 | 代表能力 | 相对 PickGlobal |
| --- | --- | --- |
| 选品工具 / 榜单 | 流量与类目热度 | 少做「算清税运费后的可审计利润」与一键进获客 |
| ERP / 打单 | 订单与仓配 | 弱于售前选品决策与线索经营 |
| 邮件 / SCRM | 群发与 CRM | 弱于与选品报告绑定的 seed，且常忽略人审与红线 |
| 纯 AI 助手 | 对话生成 | 金额不可审计；难进财务与合规讨论 |

### 6.2 壁垒

1. **规则版本化**：`rules_version` 快照；关模型仍有 metrics。  
2. **产品边界清晰**：只两条路径；销售话术与工程演进一致。  
3. **KPI 契约**：八率五时效写进产品与文档；分母 0 →「—」。  
4. **账本与支付**：验签入账、幂等键；分成可追责。  
5. **多端同一工作台**：降低切换成本，提高 ActR。

壁垒需要时间与数据加深（真实货架、送达质量、召回样本）。种子轮投资买的是**把契约做成规模化运营系统**的时间窗口。

## 8. 增长与获客

### 8.1 种子轮 GTM

1. **演示驱动**：官网教程 + 销售同屏走 demo3 路径（守则 → 路线 → 报告 → 九路 → 八率五时效）。  
2. **内容与案例**：用「规则不改数」和「分母为 0 显示横杠」做差异化内容。  
3. **渠道**：工厂社群、跨境服务商、代理（B4）共建；RAAS（B9）卖结果。  
4. **产品内增长**：邀请奖励、年付折扣、货源刷新升级促成免费→成长。

### 8.2 北星与运营动作

| 指标 | 种子轮运营含义 |
| --- | --- |
| ActR | 报告页 CTA 与教程是否讲清「一键获客」 |
| QR | 发现质量与 enrichment；低则先修线索而非加投放 |
| TR / 红线 | 未达送达标准不开量 |
| AR | 北星；样本量不足时不强行展示虚荣百分比 |

### 8.3 销售动作清单（种子轮）

1. **周演示场**：固定时段开放线上演示，录屏进案例库。  
2. **设计伙伴合同**：10–30 家深度使用，换周反馈与引用许可。  
3. **服务商共建**：货代 / 合规 / 摄影等周边服务商带客户进工作台，走邀请奖励。  
4. **年付推进**：对稳定使用成长档的客户推年付（0.7 × 12），改善现金流。  
5. **拒做的事**：未达送达红线前不做大规模冷邮；不用「AI 保证成交」话术。

### 8.4 漏斗假设（仅作内部规划，非业绩承诺）

```text
触达演示 → 试用开通 → 完成首份报告 → 一键获客 → 成长档付费 → 年付 / 规模档
```

每一跳都应对齐产品事件：`selection.completed`、`report` 获客、支付验签成功。漏斗坏在哪一步，就修哪一步，而不是先加广告预算。

## 10. 融资用途与里程碑

### 10.1 拟用途结构（示例权重）

| 用途 | 权重 | 说明 |
| --- | --- | --- |
| 产品与数据 | 35% | 货架接入、线索质量、缓存与 SLA |
| 合规触达 | 25% | 正式邮件通道、退订与投诉红线运营 |
| 工程与基础设施 | 20% | 可靠性、观测、小程序与支付深化 |
| 增长与内容 | 15% | 演示、案例、渠道启用 |
| 机动 | 5% | 合规与突发通道成本 |

具体融资金额、投前估值与股权比例由条款清单确定；本 BP 固定的是**用途优先级与里程碑**，而非单一数字。

### 10.2 12–18 个月里程碑

| 阶段 | 目标 |
| --- | --- |

## 11. 财务框架（种子轮）

### 11.1 原则

- 不在 BP 中编造未审计收入。  
- 订阅标价以产品配置为准（成长 ¥299/月、规模 ¥999/月，年付 0.7 折年化）。  
- 云成本已有日预算与缩容机制（见 `docs/cloudbase-cost.md`），增长前保持「用时才热」。

### 11.2 简化情景（说明性）

假设种子轮结束后 12 个月末：

| 情景 | 付费租户（成长为主） | 说明 |
| --- | --- | --- |
| 保守 | 数十席 | 深服务、高触达质量 |
| 基准 | 低三位数席 | 内容 + 渠道双轮 |
| 乐观 | 更高席数 + 少量规模档 | 需触达合规与货架 SLA 同步达标 |

投资人尽调时应查看：支付流水、租户活跃、看板分母样本、投诉与退信，而非仅看演示视频。

### 11.3 单位经济演算（说明性）

仅用于理解量级，**不是预测**：

| 假设 | 数值 |
| --- | --- |
| 成长档标价 | ¥299 / 月 |
| 年付实收（0.7 × 12） | ≈ ¥2,512 / 年 · 席 |
| 若 100 席成长档年付 | ARR ≈ ¥25 万量级 |
| 若其中 20 席升到规模档年付（¥999×0.7×12≈¥8,392） | 额外约 ¥17 万量级 |

结论：种子轮价值不在「立刻做出千万 ARR」，而在验证 **付费席可复制** 与 **触达可合规放量**。达到三位数付费席且红线可控，即具备下一轮叙事。

### 11.4 成本侧要点

- 云托管可缩到最小副本 0；演示站冷启动可接受。  
- 规则算利润不依赖大模型 token；AI 费用与解释 / 文案用量挂钩。  
- 正式邮件与 enrichment API 按用量计费，应计入毛利，不可只算订阅价。  
- 账本与支付回调失败可回退，避免「假成功」造成退款黑洞。

### 11.5 退出与下一轮叙事

下一轮（Pre-A）故事应建立在：**可审计的经常性收入 + 稳定的触达红线 + 可复制的选品→获客闭环**，而不是「又接了一个大模型」。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 海外邮件 / 社交合规 | 无法放量触达 | 人审强制；红线限流；分市场开通 |
| 货架 API 不稳定 | 选品体验波动 | 多源 + 缓存 + 本地演示降级 |
| 模型厂商政策 | 解释与文案中断 | 规则路径不断；多模型兼容层 |
| 云成本失控 | 毛利恶化 | 最小副本 0、日预算闸门、禁止无意义探活 |
| 范围蔓延 | 工程失焦 | 产品硬约束：只两条路径 |
| 数据与隐私 | 信任与监管 | 登录前法律同意；审计与租户隔离 |

### 12.1 为什么是种子轮、而不是再自筹半年

1. **产品契约已可演示**：两条路径、规则金额、人审触达、八率五时效均已在 demo3 成片与线上站点可见。  
2. **下一跳是资本密集的合规与数据**：正式海外触达、多货架 SLA、设计伙伴深度服务——适合与专业资本共担。  
3. **窗口**：市场仍在用「AI 选品 / AI 群发」讲故事；可审计产品有机会在买家变挑剔前占住「财务与合规也能听懂」的位置。  
4. **纪律已在**：分支保护、版本号、云日预算、禁止直推生产——降低融资后治理摩擦。

### 12.2 投资逻辑（Thesis）

> 跨境卖家需要的不是更多聊天机器人，而是 **一张算得清的选品报告**，以及 **一条批得过的获客流水线**。PickGlobal 把两者焊在同一租户、同一 KPI、同一账本上。种子轮购买的是：把这条焊点从「演示」扩成「可收费、可红线运营的系统」。

若投资人认同：

- 金额必须可审计；  
- 触达必须可批准；  
- 空样本必须显示「—」；  

则本轮用途与里程碑与之一致。若不认同，产品路线也没有空间改成「模型改价 + 自动群发」——那不是我们的公司。

## 13. 附录

### 13.1 八率（滚动 30 天；分母 0 →「—」）

| 代号 | 名称 | 公式要点 | S2 目标 |
| --- | --- | --- | --- |
| N% | 利润率 | 报告 `net_margin` 中位数 | 推荐 ≥15% |
| ActR | 行动率 | 一键获客或采纳 ÷ 完成报告 | ≥50% |
| TR | 触达率 | 送达人数 D ÷ 受众 A | ≥95% |
| OR | 打开率 | 独立打开 ÷ D | ≥40% |
| **AR** | **获客率（北星）** | 有效获客 W ÷ D | **≥8%** |
| QR | 线索合格率 | 质量分达阈值 ÷ 入库线索 | ≥60% |
| ActR_cold | 冷客激活率 | 冷启打开或回复 ÷ 入队 | ≥25% |
| RecR | 召回成功率 | 回暖 ÷ 召回已送达 | ≥10% |

红线（按封）：送达率 ≥95%；退信 &lt;1.5%；投诉 &lt;0.1%。

### 13.2 五时效（P50）

| 代号 | 名称 | 目标 |
| --- | --- | --- |
| AnaT | 分析时效 | ≤2 分钟 |
| LeadT | 线索时效 | ≤3 分钟 |
| AcqT | 获客时效 | ≤3 天 |
| ActT | 激活时效 | ≤24 小时 |
| RecT | 召回时效 | ≤24 小时 |

### 13.3 利润公式（规则引擎）

```text
R = 目标售价 USD
C = 采购折美元 + 包装 + 国内段 + 国际段
F = R × (平台费率 + 支付费率)
T = 关税等
N = R − C − F − T
利润率 = N / R
```

落库必带：`net_margin`、`net_profit_usd`、`fx_usd_cny`、`rules_version`。
