## 日预算闸门（0.3 元）

| 规则 | 说明 |
| --- | --- |
| 每次开站 | 必须跑脚本（见下）。扫库不算额度，也不应当成正式启动 |
| 每天次数 | **3 次**，每次记 **0.1 元** |
| 每天上限 | **0.3 元**；第 4 次脚本会拒绝，等到第二天 |
| 0.1 元能热多久 | 两套 0.25C/0.5G 同开 ≈ **0.06 元/时** → 大约 **1 小时 40 分**；你离开后还会再计约 30 分钟冷却 |
| 状态文件 | `docs/cloudbase-budget-state.json`（上海时区按天重置） |

正常营业时 AccessTypes 为 `PUBLIC`（自定义域名需要）。预算关闭时故意改成 `OA`（站点会 403），直到 `--cursor-start` 或次日。

不要用定时 HTTP 探活网站。空闲巡检只读副本 / 调用量。本机 `com.yourorg.monitor_daemon` 已停用。

不该动：共享 PostgreSQL `postgres-hn5po6jy`、静态托管、云存储、云函数命名空间、mornfront 环境。

单价（上海云托管，1000 资源点 = 1 元）：CPU 55 点/核时，内存 32 点/GB 时。一套 0.25C/0.5G ≈ 0.03 元/时；两套同热 ≈ 0.06 元/时。每次 0.1 元大约够两套热着约 1.7 小时（含约 30 分钟冷却）。


或控制台：运行模式 **始终自动扩缩容**，规格 **0.25C/0.5G**，最小 **0**，最大 **1**，访问 **公网 PUBLIC**（预算未关闭时）。

## 禁止

- 销毁环境、冻结云托管、删除当前流量版本、删除 PostgreSQL。
- 关掉超量按量（配额用尽会直接停服）。
- 把流量切到旧版本，或把最大副本改成 0。
- 对生产域名做高频探活（会烧掉日预算）。
- 在预算未关闭时把手改成非 `PUBLIC`（会弄挂自定义域名）；预算关闭由脚本改 `OA` 是预期行为。
